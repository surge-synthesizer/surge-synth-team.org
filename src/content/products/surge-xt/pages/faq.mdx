<FaqItem q="If I make sounds or songs with Surge XT, can I distribute, sell or commercially license them?">

Yes.

Surge XT is free and open source software released under GPL3, a license which governs what happens
if you modify the Surge XT source code or distribute a binary of it. GPL3 does not constrain your
use of Surge XT in your music in any way.

If you make songs, samples, sounds, patches, glitches, noise bombs, soundscapes, videos, movies, dog
beats or any other intellectual property using Surge XT, you own it, and you need no license or
permission from us or anyone else. That applies whether your sounds are given away for free or
commercially licensed and sold, and whether you started a patch from scratch or from one of the
factory presets. The output of Surge XT is yours to do with as you want.

</FaqItem>

<FaqItem q="Where is Surge XT installed on Windows?">

Surge XT installs to the default VST3 and CLAP plugin paths:

- 32-bit VST3 - `C:\Program Files (x86)\Common Files\VST3\Surge Synth Team\`
- 64-bit VST3 - `C:\Program Files\Common Files\VST3\Surge Synth Team\`
- 32-bit CLAP - `C:\Program Files (x86)\Common Files\CLAP\Surge Synth Team\`
- 64-bit CLAP - `C:\Program Files\Common Files\CLAP\Surge Synth Team\`

We advise you not to move the plugin to any other folder on your system, and not to move the
`C:\ProgramData\Surge XT\` folder anywhere else either, or bad things will happen.

</FaqItem>

<FaqItem q="Where is VST2?">

As of the Surge 1.7.0 release we distribute built binaries only as VST3 and AU.

VST2 is not free and open source software, and Steinberg, the copyright owner of VST2, no longer
makes licenses available to developers. With Surge 1.7.0 we moved to binary distributions which are
free and open source only. If you require VST2, here are your choices:

- Download Surge builds older than 1.7.0
  [here](https://github.com/surge-synthesizer/surge/tags?after=release_1.7.0).
- If you have the VST2 SDK and a valid license, build Surge XT from source yourself. Building the
  plugin is rather easy - a single environment variable activates the VST2 build. Even though we do
  not distribute a VST2, members of the dev team test it from time to time to make sure it still
  runs.
- Consider one of the VST2 stub alternative libraries. If you manage to make Surge XT work with one
  of these, we would happily merge any changes required so that future builders could do the same,
  although we would be reluctant to include such a build in our binary releases for license clarity
  reasons.

</FaqItem>

<FaqItem q="Where is LV2?">

As of the Surge 1.7.0 release we distribute built binaries only as VST3 and AU.

We made this choice because parts of the current LV2 specification and Surge XT are incompatible in
several ways. Most importantly, LV2 assumes that plugins never modify their control input ports.
Actions like changing parameter types when an effect changes, or changing patches, are not
compatible with that constraint. As a result LV2, especially in Ardour, does not save and restore
state reliably. The solution is to use new LV2 APIs that allow current Surge XT behaviour and match
what other plugin standards do. If you are an LV2 expert who is motivated to help us fix this,
contact us on [Discord](https://discord.gg/spGANHw). We would welcome any help.

</FaqItem>

<FaqItem q="I am a Pro Tools user. What about us?">

Unfortunately, since AVID binds their AAX plugin format to the iLok copy protection mechanism and a
signing procedure, both of which are closed source, we cannot support the AAX plugin format at all.

You can, however, use a third party plugin host or chainer such as Blue Cat Patchwork or Kushview
Element to load the Surge XT plugin in a roundabout fashion.

</FaqItem>

<FaqItem q="How do I run Surge XT? I installed it and all there is is a VST3 in the directory above!">

Surge XT is primarily an instrument plugin rather than a standalone program. It does come with a
standalone executable if you want one - it is a checkbox during installation. To run the plugin,
though, you need a DAW (digital audio workstation) or another type of host that supports VST3 or, on
macOS, AU plugins. Without a host you will not be able to run Surge XT as a plugin.

A variety of free and paid hosts will work. Cubase, Reaper, Live, Logic, Bitwig and FL Studio are
among the popular paid hosts, and many are multi-platform. For free hosts: on Linux, Ardour and
Carla are popular; on macOS, GarageBand is a free option, as is Hosting AU, a lightweight AU
wrapper; on Windows, Cakewalk Sonar is a good free DAW and SAVIHost an excellent free plugin
wrapper. There are many more - this list is illustrative, not exhaustive.

</FaqItem>

<FaqItem q="Surge XT doesn't show up in Ableton Live!">

First, make sure you are running at least Live 10.1, since Live did not support VST3 plugins before
that version. Second, make sure Preferences > Plug-ins > Use VST3 Plug-In System Folders is set to
On.

</FaqItem>

<FaqItem q="I'm using Ableton Live 11 and getting odd note hangs and stuff!">

Ableton Live 11.0 MPE mode transforms non-MPE events into MPE events without sending an "MPE is
activated" event when it does so. If you use Surge XT in Live 11 and get occasional stuck notes, you
need either to make the Live device not an MPE device, or to make Surge XT enter MPE mode by
clicking the MPE button next to the Patch Browser.

Live 11.0.5 fixes this issue, so make sure you are updated to at least that version.

</FaqItem>

<FaqItem q="Should I put user content in the Factory folder?">

No. It's the Factory folder.

At startup Surge XT scans for all content - skins, patches, wavetables and so on - in both the
Factory folder and the User folder on your system. The Factory folder is installed in an
administrator-writable central location, and the User folder is in your user documents area. The
locations are listed in the manual, and you can always find them on Surge XT's about page
(Menu > About Surge XT).

If you put user content in the Factory folder, or otherwise change it, the next time you update
Surge XT the installer will erase it completely. Our installers never touch anything in the user
area.

</FaqItem>

<FaqItem q="I'm using Arch Linux and Surge XT for VCV Rack won't load!">

The Arch AUR package `vcvrack` produces a binary which is incompatible with the VCV Rack Library
build of some plugins, including Surge XT and, recently, Free (formerly Fundamental). Your options
are:

- Don't use the AUR package `vcvrack`. Instead [download VCV Rack
  directly](https://vcvrack.com/Rack#get), or use the AUR package `vcvrack-bin` to do the same.
- Don't use Surge XT from the Rack library - compile it yourself instead.

We have informed the maintainers of the `vcvrack` package of this problem, and will update this FAQ
if the situation changes.

</FaqItem>

<FaqItem q="I got a 404 on the nightly page!">

Nightlies come at you fast around here. We build a new one for each commit, and uploading the
binaries to GitHub takes a couple of minutes. If you are unlucky enough to try to download a nightly
while the upload is still going on, you will get a 404. Try again in a few minutes and you should be
fine.

</FaqItem>

<FaqItem q="How do I make a feature request?">

Feature requests are the source of some of the best ideas in Surge XT and we love to have them. But
Surge XT also has a lot of features, so what you want may already be there.

The best mechanism for a feature request is to suggest it on our
[Discord](https://discord.gg/spGANHw), in either the `#using-surge` or `#🔨surge-development`
channel, and see whether someone says "oh, you can already do that", or "oh, that's totally
impossible for reason XYZ", or "oh, we already have that as a feature request". If it is none of
those, please open a [GitHub
issue](https://github.com/surge-synthesizer/surge/issues/new/choose) with the feature request, and
perhaps a synopsis of the Discord conversation. We will add it to an upcoming milestone, depending
on complexity and the various other priorities we constantly juggle.

</FaqItem>

<FaqItem q="I have a question and need help. What should I do?">

Join our [Discord server](https://discord.gg/spGANHw), hop into the `#❓help` channel and ask.

To make things quicker: share your OS and your DAW if you are using one, be as specific as possible,
and let us know whether you are using a screen reader. Copying the information from Surge XT's about
screen often helps too. Finally, just ask - no need to ask whether you can ask.

</FaqItem>
